# Визуализация сети муниципальных экономик

Одностраничное приложение: сеть экономической близости МО, раскрашенная
по типам локальных экономик из `clustering.ipynb`.

## Данные

Приложение читает единственный файл `public/network.json`. Его готовит скрипт
`viz/export_network.py` из результатов ноутбука — тех самых `results/*.csv`,
которые сохраняет последняя ячейка `clustering.ipynb`:

```bash
# из корня проекта, после прогона clustering.ipynb
python viz/export_network.py
```

Нужны три файла: `results/clusters.csv`, `results/network_edges.csv` и
`results/mo_features.csv` (из него берутся координаты центроидов). Если рядом
лежит `results/feature_importance.csv`, из него собирается диаграмма важности
признаков; без него страница просто обойдётся без неё.

**Названия типов задаются в самом скрипте**, в словаре `TYPE_NAMES`. Ноутбук
пишет в `clusters.csv` то, что лежит в `names_by_cluster` — при черновой
разметке это перечисление главных отличий. Чистовые названия берутся из
скрипта, черновые остаются на странице в сворачиваемом блоке под таблицей.
После каждого нового прогона `TYPE_NAMES` надо сверить с медоидами: нумерация
типов между прогонами не сохраняется. Скрипт
считает силовую раскладку с фиксированным seed — на полутора тысячах узлов это
примерно полминуты, зато картинка одинаковая при каждом открытии страницы.

Пути можно задать явно:

```bash
python viz/export_network.py --results путь/к/results --out viz/public/network.json
```

## Запуск

```bash
cd viz
npm install
npm run dev      # http://localhost:5173
npm run build    # проверка типов + сборка в dist/
npm run preview  # посмотреть собранное
```

## Деплой на Vercel

Root Directory — `viz`, остальное берётся из `vercel.json`: команда сборки
`npm run build`, каталог `dist`. Файл `public/network.json` попадает в сборку
как статический, поэтому его нужно сгенерировать до деплоя и закоммитить.

## Как устроен код

| Файл | За что отвечает |
|---|---|
| `src/data.ts` | загрузка `network.json`, проекция координат, подготовка массивов |
| | здесь же сдвиг отрицательной долготы: Чукотка заходит за 180-й меридиан, и без сдвига её МО уезжают к левому краю карты |
| `src/view.ts` | камера (масштаб и сдвиг), переход между раскладками, поиск узла под курсором |
| `src/render.ts` | рисование рёбер и узлов на canvas |
| `src/theme.ts` | палитра; цвета читаются из CSS-переменных, поэтому тёмная тема задаётся в одном месте |
| `src/main.ts` | сборка страницы и обработка событий |
| `src/style.css` | оформление и обе темы |

Рисование идёт на canvas: полторы тысячи узлов и пять тысяч рёбер
в SVG дают столько же DOM-узлов, и перетаскивание начинает заметно тормозить.

Цвета типов проверены на различимость при дальтонизме и на контраст к своей
поверхности в обеих темах. Цвет нигде не остаётся единственным носителем смысла:
тип подписан в таблице и во всплывающей подсказке.
